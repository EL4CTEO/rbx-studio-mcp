# v0.9.0 validation

Validated locally on Windows on 2026-10-06, starting from clean main at v0.8.7 commit `14714d04249f3ee86ea58676c454f855c7185b04`. The live-tested plugin fingerprint was `adcec0f02070`; the connected editor reported version 0.9.0, matching sources, and no protocol mismatch. Studio reported 0.741.19.7411056.

The release fingerprint is `fa0b6af1a593`. After the live pass, only whitespace on one blank line in ViewRead changed; its compiled Luau bytecode was checked and is byte-identical. No runtime behavior changed after the final live tests.

## Automated checks

- `npm run typecheck`: passed.
- `npm run build:all`: passed, including Luau compilation, unexpected-global checks and the client clone dependency graph.
- `npm test`: passed in full. Covers existing transport, console, playtest, undo, editor, sync, Open Cloud and result-budget behavior as well as the new reader routing, handles, snapshot and watch regressions.
- Real Luau module tests cover immutable snapshots, projected pages, complete UTF-8 strings, escaped control characters, capacity/expiry, mixed-key tables, long dictionary-key summaries, stale/wrong-context handles, duplicate paths, listener cleanup, bounded watch baselines, Unicode clipping and oversized first-log loss metadata.
- A fresh stdio MCP client listed exactly 35 tools.
- Package creation and file checks passed using a workspace-local npm cache. The roughly 740 KB archive includes the server, all new plugin source modules, plugin builder/installer, changelog and both v0.9.0 notes. As before, installation builds the plugin XML from its packaged sources.

One early full run failed the existing sync-watch timing assertion that a Studio edit reaches disk. The isolated suite and two subsequent full runs passed without changing sync implementation or weakening the assertion. This does not establish that the original timing failure is impossible; retain it as a possible test race to investigate if repeated.

## Real Studio checks

The user authorized INCIDENT: Blackwood for testing. Editor operations were reads and playtest control. All instance/script changes were confined to temporary runtime fixtures and actual-client GUI; the test then stopped the playtest.

The public v0.9.0 CLI tools were called through a fresh SDK client, rather than relying on the existing application's older cached schemas. Fourteen functional checks passed:

1. Create, modify, move and delete work during playtests, including a bare duplicate name and a dot-containing folder name.
2. Font enum and FontFace datatype conversion remain distinct; Font=Code reads back as Enum.Font.Code.
3. Script edits apply and stale revisions refuse a later overwrite.
4. A handle survives rename, addresses the same instance, and refuses a deleted instance.
5. A 140-row Studio execution result is fully paged with field projection; its mutation counter stays at one.
6. Actual-client execution returns same-named siblings and reports the client VM/script identity.
7. Client tree/find/inspect see client-only UI, preserve duplicate identity and reject a client handle in the Studio scope.
8. Client UI audit inspects the actual PlayerGui and finds both test elements.
9. Client performance snapshot returns real client render counters without the server's no-renderer warning.
10. A client-only GUI path crops to the expected pixels with IgnoreGuiInset=true.
11. A second crop matches the expected pixels with IgnoreGuiInset=false.
12. Normalized viewport picking uses the game's actual camera and returns the expected runtime instance and a usable handle.
13. A returned long JSON string containing Unicode is reconstructed completely across client pages after the execution relay is gone.
14. A concurrent client watch captures property, attribute, child-added and child-removed events with no dropped events.

Both GUI crops were checked for the fixture's actual pixel coverage, then viewed manually. Accepting an image block or a non-flat capture alone was insufficient: that weaker check initially accepted a shifted crop, which is why the pixel assertions were added.

Cleanup also passed: game attributes remained empty, Workspace returned to its original 31 children, and the temporary fixture was absent from the editor. Session listing showed only the editor after stop. This verifies those baseline conditions and the absence of editor write calls; it is not a full serialization diff of the authored place.

## Defects caught before handoff

- Weak instance wrappers could be collected despite their engine objects remaining parented. Handles now use a bounded strong-reference cache.
- Extracting shared viewport code omitted a UI constant and the editor's vector helper. Shared readers and static global checks now cover both.
- ScreenGui positions use the inset coordinate origin regardless of IgnoreGuiInset. Cropping and screen-bound auditing now translate both settings correctly.
- Watch initial attributes bypassed the event budget; initial values now count against the same cap.
- A single oversized printed line lacked an omission count; snapshots/replies now retain that metadata.
- A child summary with many long dictionary keys could exceed the page budget and return a non-advancing cursor; summaries are bounded and an unrepresentable address produces an explicit error.

The original picking fixture tried to set Blackwood's camera, which its own controller replaced. The final test creates the fixture along the current camera's ray and does not change that controller.

## Repeat the live suite

Build and install the plugin, focus Studio to reload it, and connect one editor with playtests enabled. The suite starts and stops its own test and refuses an already-running playtest:

```text
npm run build:all
npm run install:plugin
npm run test:live:v090
```

With multiple editors, use `npm run test:live:v090 -- --studio-id <editor-id>`. Generated reports and images are in the ignored build folder: `live-v0.9.0.json`, `live-v090-crop.png` and `live-v090-inset.png`.

This was a single-player desktop Studio pass. Multiplayer/player-disconnect races, mobile/VR safe areas, rotated/world-surface GUI crops, profiler accuracy and production Open Cloud were not live-tested. Existing offline checks cover relevant unchanged behavior, but that is not a substitute for those live scenarios.

The final suite was repeated successfully after reconnecting the MCP, against the same plugin fingerprint. Consumers must update both server and plugin and reconnect their MCP client to load the new schemas. npm publication is handled separately by the package owner.
